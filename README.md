# Цель проекта

Командно разработать прототип интеллектуального ассистента, который помогает студенту МГТУ им. Г. И. Носова получать ответы на типовые вопросы, связанные с обучением и университетской жизнью.

Ассистент должен использовать технологии искусственного интеллекта для поиска и обработки информации, формирования ответов на естественном языке и, при необходимости, взаимодействия с инструментами и структурированными данными.

Главная задача проекта — не просто создать работающего чат-бота, а исследовать возможности и ограничения ИИ-системы, научиться измерять её качество, выявлять ошибки и оценивать целесообразность применения такой системы.

## Возможные вопросы ассистенту

Например:

* Где находится расписание занятий?
* Как узнать академическую задолженность?
* Какие документы необходимы для оформления справки?
* Как получить справку об обучении?
* Когда начинается сессия?
* Какие правила действуют при пересдаче?
* Где найти информацию о практике?
* К кому обращаться по определённому вопросу?
* Какие услуги доступны студенту?
* Где находится нужная кафедра или подразделение?
* Какой размер повышенной стипендии?

Конкретный набор функций определяется командой на этапе проектирования.

## Основной результат

К концу семестра команда должна представить работающий прототип ИИ-ассистента, с которым можно взаимодействовать, а также комплект документации, позволяющий другому пользователю запустить систему и оценить её качество.

Проект должен включать:

1. сформулированную целевую задачу и требования;
2. подготовленную базу знаний;
3. разработанную архитектуру системы;
4. реализацию RAG и/или других компонентов ИИ;
5. при наличии обоснования — агентную часть и использование инструментов;
6. пользовательский интерфейс;
7. систему тестирования;
8. собственный benchmark минимум из 100 тестовых сценариев;
9. количественную оценку качества;
10. анализ ошибок, рисков и ограничений;
11. оценку экономической целесообразности;
12. документацию по установке, запуску и использованию.

## Ограничения проекта

### Аппаратные ограничения

Проект должен разрабатываться с учётом отсутствия GPU.

Не допускается использование GPU как обязательного ресурса для работы готовой системы.

Допускается:

* CPU-инференс;
* Google Colab;
* локальный запуск небольших моделей;
* использование готовых моделей;
* квантованные модели;
* удалённые вычислительные ресурсы, если они доступны бесплатно и не являются обязательными для воспроизведения проекта.

### Финансовые ограничения

Не допускается использование платных подписок и платных API для обязательной функциональности проекта.

Проект должен иметь работоспособный вариант с использованием бесплатных или локальных инструментов.

### Использование ИИ при разработке

Разрешается использовать GigaChat, YandexGPT, ChatGPT, Claude, Gemini, Qwen и другие ИИ-инструменты для:

* написания и отладки программного кода;
* анализа ошибок;
* подготовки документации;
* генерации тестовых данных;
* подготовки презентации;
* поиска вариантов архитектуры;
* анализа результатов.

Однако использование ИИ должно быть осознанным и задокументированным.

Команда обязана фиксировать существенные запросы к ИИ и результаты их использования в отдельном разделе репозитория проекта.

Недопустимо выдавать результат работы ИИ за собственный анализ без проверки.

### Основной принцип проекта

ИИ может помогать разрабатывать систему, но не может быть доказательством того, что система работает правильно.

Поэтому команда должна самостоятельно определить:

* что считается правильным ответом;
* какие ошибки наиболее критичны;
* как измеряется качество;
* когда система должна отказаться от ответа;
* какие риски существуют;
* в каких случаях применение ИИ нецелесообразно.

## Итоговая защита

В конце семестра каждая команда:

1. демонстрирует работающего ИИ-ассистента;
2. представляет архитектуру и результаты разработки;
3. демонстрирует результаты тестирования;
4. показывает собственный benchmark;
5. демонстрирует найденные ошибки и ограничения;
6. проводит оценку экономической целесообразности;
7. предоставляет другой команде возможность протестировать систему;
8. с использованием benchmark другой команды проводит независимую оценку её ИИ-ассистента.

Итоговая оценка каждого проекта складывается из:

* оценки преподавателя;
* оценки других команд.
